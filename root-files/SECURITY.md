# Security Policy

## Supported Versions

| Version | Supported |
| --- | --- |
| Latest stable | Yes |
| Earlier versions | Define policy |

## Reporting A Vulnerability

Do not report suspected vulnerabilities through a public issue.

Use the project's approved confidential channel:

```text
{{SECURITY_REPORTING_CHANNEL}}
```

Include:

- affected version, component, and environment;
- reproduction steps or proof of concept;
- expected and observed behavior;
- potential impact;
- known mitigations;
- a safe way to contact the reporter.

Do not include real secrets, personal information, or unnecessary production
data.

## Response Process

State:

- when receipt should be acknowledged;
- how severity and affected versions are assessed;
- how fixes and coordinated disclosure are handled;
- when the reporter can expect status updates;
- how credit is handled.

## Scope And Safe Harbor

Describe authorized testing boundaries and obtain legal review before promising
safe harbor or other legal protection.

## Security Design

Current security design, data handling, and threat models are maintained under
`docs/security/`.
