# Product Documentation

Product documents define the problem, intended users, outcomes, constraints,
and accepted requirements. They explain why the project exists and what success
means without prescribing implementation details that belong in design
documents.

- [`vision.md`](vision.md) captures durable product intent and boundaries.
- [`requirements/`](requirements/) contains testable product requirements.

Research observations belong in [`notes/`](../notes/) until the project accepts
them. Implementation sequencing belongs in [`plans/`](../plans/).
