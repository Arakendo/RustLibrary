# Guides

Guides help a reader complete a task. They should be goal-oriented, tested
against the supported environment, and explicit about prerequisites and
expected results.

Typical guides include:

- getting started;
- local development setup;
- deployment;
- integration walkthroughs;
- troubleshooting;
- contribution workflows.

Stable facts such as configuration keys belong in [`reference/`](../reference/).
Current architecture belongs in the project or subsystem design documents.

Copy `TEMPLATE.md` to a descriptive lowercase filename and add it to the index.
